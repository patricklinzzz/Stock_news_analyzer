# 台股新聞訊號分析系統 Stock News Analyzer

用免費工具打造的台股即時新聞蒐集與訊號驗證系統。目標不是直接做出一個「新聞預測股價」的黑盒子,而是先老老實實驗證:**新聞資訊到底能不能作為投資的輔助訊號**,有證據再往下做,沒有就誠實承認。

## 這個專案在做什麼

```
多來源RSS新聞抓取 → 去重 → 股票比對 → 存入資料庫(每天自動執行)
                                            ↓
                    新聞量 vs 股價隔日報酬 → 相關係數 + 統計顯著性(每週自動執行)
```

分兩條自動化管線,全部跑在 GitHub Actions 上,不需要自己的伺服器,也不用付費 API。

---

## 專案結構

```
.
├── stock_news_analyzer.py         # 主程式:抓新聞、去重、比對股票、寫入DB
├── backtest_analysis.py           # 回測分析:新聞量 vs 股價報酬的相關性驗證
├── find_unmatched_companies_v2.py # 輔助工具:找出常上新聞但還沒被涵蓋的公司
├── news.db                        # SQLite資料庫(自動產生,每天累積)
├── backtest_results/              # 回測結果(自動產生)
│   ├── backtest_YYYY-MM-DD.csv    #   每次執行的完整資料快照
│   └── summary_log.csv            #   長期追蹤用的相關係數/p-value歷史記錄
└── .github/workflows/
    ├── fetch_news.yml             # 排程:每個交易日自動抓新聞
    └── weekly_backtest.yml        # 排程:每週自動跑一次回測分析
```

## 功能說明

### 1. 新聞蒐集(`stock_news_analyzer.py`)

- **新聞來源**:Google News、中央社(CNA)、Yahoo奇摩台股,皆為免費公開 RSS
- **股票對照表**:內建 37 檔台股常見標的(涵蓋台灣50主要成分股),含公司全名與常用別名
- **去重機制**:
  - URL 層級:同一則新聞用 `hash(url)` 天然去重
  - 標題相似度層級:用 `difflib` 比對標題相似度,擋掉不同媒體轉載同一則新聞的情況,並優先保留可信度較高來源的版本
- **股票比對**:字串比對法,判斷每則新聞提到哪些股票代號
- **資料庫結構**:兩張正規化表格
  - `news_raw`:新聞本體(標題、連結、來源、發布時間)
  - `news_stock_map`:新聞與股票的多對多對應關係

### 2. 回測驗證(`backtest_analysis.py`)

驗證邏輯很陽春,故意先不做情緒分析,只看最基本的訊號:

1. 從 `news.db` 算出每檔股票每天被提到幾次(新聞量)
2. 用 `yfinance` 抓對應股票的歷史股價,算出隔日報酬率
3. 把兩者對齊,計算**相關係數**與 **p-value(統計顯著性)**

輸出:
- `backtest_results/backtest_YYYY-MM-DD.csv`:當次完整資料快照
- `backtest_results/summary_log.csv`:每次執行新增一列,長期累積成趨勢記錄

### 3. 擴充股票對照表覆蓋率(`find_unmatched_companies_v2.py`)

股票對照表不是加越多越好(詳見下方「已知限制」),但清單裡缺漏常上新聞的公司還是要補。這支工具用來找出候選名單:

1. 從證交所免費、不需申請金鑰的官方 OpenAPI 抓「全部上市公司基本資料」(`https://mopsfin.twse.com.tw/opendata/t187ap03_L.csv`)
2. 排除掉已經在對照表裡的股票
3. 拿官方公司名稱去比對「完全沒被比對到任何股票」的新聞標題
4. 印出出現次數夠多、且尚未涵蓋的公司候選,附上範例標題

因為是跟官方登記名稱比對,不是用詞頻猜測,所以不會出現「反彈」「分析師」這類雜訊詞。但**仍需要人工確認**,原因是公司簡稱可能跟其他實體(尤其是外國公司)撞名——例如台股代號 5007 的「三星」,新聞裡若提到的其實是韓國三星電子,直接加進對照表會造成誤判,汙染後續的回測資料。

> 目前只涵蓋「上市」公司,不含「上櫃」,之後可視需求擴充串接櫃買中心(TPEx)的對應 OpenAPI。

## 快速開始

### 安裝依賴套件

```bash
pip install requests feedparser pandas yfinance scipy
```

### 手動執行

```bash
# 抓新聞、比對股票、寫入資料庫
python stock_news_analyzer.py

# 跑回測分析(建議累積至少2-3週資料再執行,不然結果不可信)
python backtest_analysis.py

# 找出常上新聞但還沒被涵蓋的公司候選(建議累積1-2週資料後再跑)
python find_unmatched_companies_v2.py
```

### 自動化(GitHub Actions)

repo 裡已經放好兩個排程:

| Workflow | 排程時間 | 功能 |
|---|---|---|
| `fetch_news.yml` | 每個交易日台灣時間 08:30 | 抓新聞、寫入資料庫、自動commit回repo |
| `weekly_backtest.yml` | 每週一台灣時間 09:00 | 跑回測分析、自動commit結果回repo |

**部署前記得開權限**:Settings → Actions → General → Workflow permissions → 選「Read and write permissions」,不然 workflow 最後的 `git push` 會失敗。

兩個 workflow 都支援 `workflow_dispatch`,可以在 Actions 頁面手動觸發測試,不用乾等排程時間。

> 補充:GitHub Actions 的 `schedule` 觸發是「盡力而為」(best-effort),不保證準時,官方文件寫明高負載時段可能延遲。這對本專案(每天批次收集資料)不影響實際使用,不用太在意執行時間有沒有準點。

## 如何解讀回測結果

打開 `backtest_results/summary_log.csv`,看 `overall_correlation` 和 `p_value` 這兩欄隨時間的變化:

| 情況 | 代表什麼 | 建議 |
|---|---|---|
| p-value 持續 < 0.05,且隨資料增加越來越穩定 | 新聞量可能是有效訊號 | 可以往下拆解到個股層級,並做樣本外驗證(out-of-sample)排除過度擬合 |
| p-value 持續 > 0.05,或相關係數忽正忽負沒有固定方向 | 純新聞量不是有效訊號(這是預期中的常態結果,不代表專案失敗) | 考慮轉向情緒分析(不只看新聞則數,還要看內容正負面)或事件分類 |

**重要提醒**:資料量太少時(例如少於 14-21 天),相關係數和 p-value 都不可靠,只能當雜訊看待。這個系統的設計本來就需要時間累積資料,不是跑一次就能下結論的工具。

## 已知限制

- 股票比對用純字串比對,沒有做中文分詞,別名清單刻意避開太短、太通用的字詞以降低誤判,但仍可能有漏抓或誤判的情況
- 公司簡稱可能跟其他實體(尤其外國公司)撞名,擴充對照表時需人工確認情境,不能只看出現頻率就直接加入(參考 `find_unmatched_companies_v2.py` 的說明)
- 新聞來源目前只有 3 個,覆蓋率有限,尤其是非權值股的相關新聞可能抓不到
- 股票對照表目前只涵蓋「上市」公司,不含「上櫃」
- 回測邏輯只驗證「新聞量」這個最陽春的訊號,還沒有做情緒分析、事件分類等更細緻的處理
- `news.db` 用 SQLite 並直接 commit 進 git repo,規模變大之後(例如累積超過一年)可能需要換成其他儲存方案
